# ADR-0001: один monorepo и короткие ветки

Дата: 2026-07-28 · Статус: принято

## Контекст

Backend, frontend, Vision и схемы меняются совместно. Раздельные репозитории
потребовали бы синхронизации версий контрактов ещё до появления независимых
релизных циклов и отдельных команд.

## Решение

Все компоненты живут в одном репозитории. `main` всегда должна проходить CI;
работа ведётся короткими тематическими ветками и вливается небольшими
проверяемыми изменениями. Общий формат сначала меняется в `contracts/`, затем в
его producer и consumer в том же pull request.

Постоянные ветки компонентов и финальный большой merge не используются.

## Последствия

- одно изменение может атомарно обновить контракт, backend и frontend;
- CI запускает независимый job для каждого компонента;
- история едина, а релиз получает один commit SHA;
- владельцы изменений обязаны не смешивать несвязанные задачи в одном commit.
