# ML / Computer Vision в Dorahub

Актуально на **2026-08-03**. Vision — экспериментальный помощник для разбора
фотографии реального стола риичи-маджонга. Он не принимает игровые решения сам:
результат всегда проверяет человек, а приложение может работать без ML.

## Что уже работает

Текущий основной путь:

```text
фото
  → CountGD++: кандидаты «здесь лежит тайл»
  → split_tile_rows.py: разделение слипшихся рядов
  → SAM2: контур каждого найденного тайла
  → layout.py: координаты стола, роли и места игроков
  → LiteRT (опционально): номиналы 37 видов тайлов
  → groups.json + цветной overlay
```

CountGD++ выбран как основной proposal detector: на наших кадрах он визуально
лучше старого YOLO/SAHI, GroundingDINO, OWLv2, RF-DETR и cvflow. Он пока отвечает
только на вопрос «это тайл», а не «какой это тайл».

`split_tile_rows.py` ищет внутри длинного светлого бокса периодические швы и
разбивает ряд на отдельные перспективные четырёхугольники. Он не дорисовывает
одиночные объекты и фон. SAM2 уточняет контур, но не может восстановить тайл,
который детектор вообще не предложил. Слишком маленькая, большая или смещённая
маска отбрасывается, тогда используется четырёхугольник CountGD++.

`layout.py` группирует найденные тайлы по геометрии, а не по фиксированным зонам
фотографии. Центр игры может быть смещён, кадр — обрезан или снят под углом. В
выходе есть роли `hand`, `opponent_hand`, `discard`, `wall`, `dead_wall`, `dora`,
`other`, `noise`, а также открытые `chi`, `pon`, `kan`.

Ограничения риичи используются как проверка результата:

- не больше четырёх игроков, рук, стен и пулов сброса;
- места: `self`, `left`, `opposite`, `right`;
- в обычном ряду сброса не больше шести тайлов;
- открытая связка содержит три тайла, кан — четыре; вызванный тайл повёрнут;
- мёртвая стена содержит до 14 тайлов, до пяти индикаторов доры находятся в ней.

Поле `sceneTiles` в `groups.json` — разреженная 3D-модель сцены. Для каждого
тайла сохраняются `[x, y, z]`, угол `yaw`, роль, место игрока, группа, номинал и
исходный box. На overlay рисуются отдельные перспективные контуры тайлов без
общих прямоугольников групп.

## Текущее качество

### Поиск тайлов: пул из 257 фото

Основной локальный набор лежит в `../test/dataset` относительно monorepo.

| Прогон | Всего кандидатов | Медиана на кадр |
|---|---:|---:|
| CountGD++ без post-process | 20 389 | 83 |
| `row-split-v3` | 20 999 | 85 |

Разделение особенно помогло слипшимся рядам: `000043` — 12→25,
`000038` — 41→75, `000225` — 37→78. На `000126` получилось 109 вместо 83
исходных кандидатов. Это количество предложений, не независимая detection
precision/recall: у всех 257 кадров ещё нет полной ручной instance-разметки.

Канонический локальный результат:

```text
test/experiments/countgdpp-dataset257/results-row-split-v3.json
test/experiments/sam2-countgd-row-split-v2/masks.json
test/experiments/countgdpp-layout-row-split-masks-v4/groups.json
```

### Роли: 8 вручную проверенных старых фото

В эталоне 545 тайлов и ещё 60 спорных `unknown`, которые не участвуют в оценке.

| Роль | Precision | Recall |
|---|---:|---:|
| `hand` | 1.000 | 0.825 |
| `opponent_hand` | 0.821 | 0.426 |
| `discard` | 0.822 | 0.702 |
| `wall` | 0.568 | 0.851 |
| `dead_wall` | — | 0.000 (0/10) |
| `dora` | — | 0.000 (0/3) |

Сводно: `falseRole = 82/382 = 0.215`, `silence = 47/429 = 0.110`,
`missedTiles = 116/545 = 0.213`. Три кадра пока без truth:
`img_77c49af06036`, `v8-test-4`, `v8-test-5`.

Худшие случаи показывают реальное узкое место: на дальних и сильно наклонённых
фото предложения тайлов есть, но роли распадаются в `wall`/`other`. Поэтому
сейчас важнее улучшать геометрию и разметку ролей, а не ещё раз обучать
классификатор номиналов.

## Быстрый повтор текущего post-process

Команды запускаются из `project/`. Сам CountGD++ и веса живут вне Git в
`../experiments/countgdpp`; его локальный wrapper — `run-mahjong.sh`.

```bash
python3 vision/scripts/split_tile_rows.py \
  ../test/experiments/countgdpp-dataset257/results.json \
  ../test/dataset \
  ../test/experiments/countgdpp-dataset257/results-row-split-v3.json

PYTHONPATH=vision/src:. python3 vision/scripts/layout_preview.py \
  ../test/experiments/countgdpp-dataset257/results-row-split-v3.json \
  - ../test/dataset \
  ../test/experiments/countgdpp-layout-row-split-masks-v4 \
  --masks ../test/experiments/sam2-countgd-row-split-v2/masks.json
```

Второй позиционный аргумент — JSON с номиналами; `-` означает, что его нет.
Подробный запуск всех вариантов — в [PIPELINE.md](PIPELINE.md).

Проверка ролей:

```bash
sed -e 's/\.jfif\.jpg"/.jfif"/g' -e 's/\.jpg\.jpg"/.jpg"/g' \
  ../test/experiments/countgdpp-old11-layout-v2-clean/groups.json | \
PYTHONPATH=vision/src:. python3 vision/scripts/score_layout.py score \
  /dev/stdin ../test/roles-truth
```

Некоторые CountGD++-артефакты сохраняют имя как `.jpg.jpg` или `.jfif.jpg`.
`sed` в команде нормализует имя перед сравнением с truth, не меняя артефакт.

Проверка кода:

```bash
PYTHONPATH=vision/src:. python3 -m unittest discover -s vision/tests -v
python3 -m json.tool contracts/vision/vision-result.schema.json >/dev/null
```

Юнит-тесты не требуют моделей. Модели, приватные фото, CVAT volumes и большие
результаты экспериментов в Git не коммитятся.

## Номиналы тайлов

Аудированная `mahjong_yolo.tflite` распознаёт 34 обычных вида и три красные
пятёрки. Для полной сцены нужен режим `--faces`; без него модель видит лишь
несколько крупных лиц и косвенно ломает группировку. LiteRT слаб на рубашках,
маленьких и сильно перспективных тайлах, поэтому номинал — отдельный второй
проход после локализации.

Top-down rectification оставлена опциональной: на одном кадре она улучшила
LiteRT с 64 до 75 лиц, но ухудшила single-class YOLO с 70 до 39 боксов. Полностью
заменять исходное фото выпрямленным нельзя; допустим только второй проход с
обратным переносом координат и объединением результатов.

## Данные и обучение

- `vision/datasets/haitaks-mahjong-layout-v2` — 209 фото и single-class `tile`
  boxes, импортированные из `haitaks/mahjong`; это baseline детектора, не
  проверка номиналов и не product validation.
- локальный COCO-архив — 1 709 train / 427 validation фото; лицензия на
  распространение не подтверждена, поэтому он и веса остаются вне Git;
- пять клубных фото стали training data: 418 размеченных generic boxes, поэтому
  больше не являются независимым acceptance set;
- синтетика проверяет формат 37 классов, но не доказывает качество на физических
  тайлах;
- мобильный набор из 257 сцен не имеет готовой полной разметки; автоматические
  7 126 face proposals нужно проверить в CVAT и разделить по сессиям съёмки.

Лучший локальный YOLO-кандидат на пяти клубных фото дал `P/R/F1 =
0.787/0.778/0.782` при пороге 0.15, но пропускает стены и иногда принимает за
тайлы бумагу или кости. Поэтому он сохранён как альтернатива, а не основной
детектор. История обучения и воспроизводимые команды — в
[TRAINING.md](TRAINING.md).

## Что пробовали и отложили

| Подход | Итог |
|---|---|
| CountGD++ | текущий основной proposal detector |
| SAM2 | полезен для контуров; не восстанавливает пропуски детектора |
| YOLO + SAHI/crops | рабочая альтернатива, но хуже перенос на весь стол |
| GroundingDINO / OWLv2 | хуже полнота или больше ложных объектов на наших фото |
| RF-DETR Nano | теряет мелкие/закрытые тайлы после resize до 384 px |
| cvflow | визуально хуже CountGD++ на текущем архиве |
| top-down | только дополнительный проход, не основной вход |

Версии, лицензии и решения о переносе кода собраны в
[UPSTREAM.md](UPSTREAM.md). Формальные продуктовые метрики и acceptance gate —
в [METRICS.md](METRICS.md).

## Следующие шаги

1. Независимо разметить роли и instance boxes хотя бы на худших кадрах, включая
   `v8-test-5`, `img_3ac5bb0b89d9` и `v8-test-3`.
2. Исправлять table-space grouping по метрике: сначала `opponent_hand` и
   отделение открытых связок от сброса, затем `dead_wall`/`dora` внутри стены.
3. Добавить в validation пьяные/косые/обрезанные кадры из разных сессий и не
   смешивать соседние фотографии между train и validation.
4. Дообучать proposal detector только на подтверждённых false negative и hard
   negative; SAM2 сам пропущенные тайлы не добавит.
5. После стабильной геометрии запускать nominal classifier на каждом вырезанном
   перспективном тайле и измерять 37-class accuracy отдельно от localization.

До независимого acceptance set автоматическое принятие результата запрещено:
ML предлагает разбор, человек подтверждает или исправляет.
