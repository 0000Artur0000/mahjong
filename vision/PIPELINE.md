# Пайплайн распознавания стола — запуск

Как прогнать фотографию стола от снимка до сгруппированных зон. Все команды
запускаются из `project/` (кроме шага 1 — он из `/tmp/`).

**Референсный прогон:** `test/new-photos-v24/` — 5 свежих тестовых фото, прогнанных
через полный пайплайн (см. анализ в конце).

Что делает пайплайн: находит тайлы на всём столе, пытается прочитать их номиналы,
нормализует сцену по найденной раскладке и разносит тайлы по ролям — рука, сброс, стена,
мёртвая стена, дора. Игровой результат из этого не выводится: любой разбор
подтверждает человек.

## 0. Окружение

Модели и `ultralytics` в репозиторий не входят. Ставится отдельно и один раз:

```bash
python3 -m venv .mlvenv
.mlvenv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.mlvenv/bin/pip install ultralytics==8.4.107 opencv-python-headless ai-edge-litert Pillow
```

CPU-сборка torch берётся намеренно: детектор гоняется на нескольких фото, а не
обучается, и полный CUDA-пакет тянет несколько гигабайт впустую.

**Если есть GPU** (RTX 5060 Ti и выше) — можно поставить CUDA-сборку для ускорения:
```bash
.mlvenv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```
Драйвер 595+, CUDA 12.8 — детектор будет работать в 3-5× быстрее.

Проверено на: Python 3.12, ultralytics 8.4.107, torch 2.13.0+cpu, opencv 5.0.0.

Артефакты, которых нет в Git:

| Что | Где взять | Зачем |
|---|---|---|
| `dorahub-tile-detector-v8-package/best.pt` | `test/dorahub-tile-detector-v8-test-only.tar.gz` | боксы тайлов на всём столе, без номиналов |
| `mahjong_yolo.tflite` | `test/mahjong-calculator-v1.0.0/assets/` | номиналы, 37 классов |

Пакет детектора — приватная сборка: часть обучающего пула с неподтверждённой
лицензией. Только для локальной проверки, не публиковать.

## 1. Детектор тайлов

Режет кадр на 12 перекрывающихся кропов, гоняет YOLO на 640 px и склеивает
дубликаты через NMS.

```bash
tar xzf ../test/dorahub-tile-detector-v8-test-only.tar.gz -C /tmp
cd /tmp/dorahub-tile-detector-v8-package
"$OLDPWD/.mlvenv/bin/python" predict.py best.pt /path/to/photos/*.jpg
```

Порог по умолчанию `--confidence 0.15`. Выше — меньше ложных боксов на бумаге и
костях, ниже — больше найденных тайлов.

Результат: `results/predictions.json` и `<имя>_tiles.jpg` с боксами.

## 2. Перевод формата

Пакет отдаёт пиксельные `[x1, y1, x2, y2]`, а группировка ждёт нормализованные
`[cx, cy, w, h]`. Шаг обязателен — без него `layout_preview.py` падает на валидации
`TileBox`.

```bash
python3 vision/scripts/detector_to_layout.py \
  /tmp/dorahub-tile-detector-v8-package/results/predictions.json \
  ../test/<run>-predictions.json
```

## 3. Номиналы (LiteRT)

Модель на 37 классов. **Обязательно режим `--faces`**: он гоняет те же 12
перекрывающихся регионов, что и детектор, и сохраняет классы. Без флага скрипт
делает один проход по всему кадру и находит единицы лиц вместо десятков.

```bash
PYTHONPATH=vision/src:. .mlvenv/bin/python vision/scripts/riichi_litert.py \
  ../test/mahjong-calculator-v1.0.0/assets/mahjong_yolo.tflite --faces --confidence 0.1 \
  /path/to/photos/*.jpg > /tmp/faces.jsonl
```

Порядок величины, по которому видно, что режим верный: **40–80 лиц на кадр стола**.
Если получилось 2–5 — забыт `--faces`, и дальше вся группировка развалится: `discard`
требует хотя бы одно лицо в группе, выбор своей руки фильтруется по наличию лиц,
`dora` и `dead_wall` — тоже. Один неверный флаг здесь выглядит как «сломанный
алгоритм».

Собрать в файл, который ждёт группировка:

```bash
python3 -c "
import json
from pathlib import Path
rows=[json.loads(l) for l in Path('/tmp/faces.jsonl').read_text().splitlines() if l.startswith('{')]
json.dump([{'image': Path(r['image']).name, 'detections': r['detections']} for r in rows],
          open('../test/<run>-faces.json','w'))
"
```

## 4. Группировка и оверлеи

Строит систему координат по крайним найденным тайлам, дополняет детекции
предложениями для рубашек и разносит боксы по ролям. Центр фотографии не
используется: смещённый и обрезанный стол обрабатывается так же, как центральный.
Контур поверхности намеренно не задаёт плоскость: круглый стол и стол, уходящий
за кадр, не имеют четырёх надёжно видимых углов.

**Предложения для рубашек.** Детектор не видит рубашки чужого цвета — на клубных
фото это стены целиком, а без стены нет ни мёртвой стены, ни доры. `propose_back_tiles`
ищет однородные области **внутри плоскости стола**, чей цвет отличается от самого
стола и которые не закрыты ни одной детекцией, и режет их на тайлы шагом из
медианного размера уже найденных. Привязки к синему нет: сравнение идёт по каналам
a/b в LAB, поэтому тени, блики, бумага и тёмный телефон, отличающиеся яркостью, не
проходят, а рубашка любого цвета проходит. Заполненность проверяется по повёрнутому
прямоугольнику — ряд тайлов лежит под углом и осевую рамку заполняет лишь наполовину.

**PYTHONPATH:** рабочее значение — `vision/src:.`: пакет лежит в `vision/src`,
а точка нужна импортам `vision.scripts.*`.

```bash
PYTHONPATH=vision/src:. .mlvenv/bin/python vision/scripts/layout_preview.py \
  ../test/<run>-predictions.json \
  ../test/<run>-faces.json \
  ../test \
  ../test/<run>
```

Результат: по картинке на кадр с подписанными зонами и `groups.json` с ролью,
местом, числом тайлов и центроидом каждой группы. Роли `noise` и нерешённые группы
намеренно не рисуются.

Быстрый просмотр:

```bash
python3 -c "
import json
for x in json.load(open('../test/<run>/groups.json')):
    print(x['image'], [(g['role'], g['seat'], g['tiles']) for g in x['groups'] if g['role']!='noise'])
"
```

## Альтернатива шагам 1-2: YOLO напрямую

Если v8-пакет не под рукой — можно использовать модель из `test/ml-run/`:

```bash
.mlvenv/bin/python -c "
from ultralytics import YOLO
model = YOLO('../test/ml-run/club-hard-neg-v8/weights/best.pt')
result = model.predict('photo.jpg', conf=0.15, iou=0.5, imgsz=640)[0]
# result.boxes.xywhn — сразу [cx,cy,w,h] в нормал. координатах
"
```

Модель слабее v8-пакета (меньше найденных тайлов), но не требует распаковки
архива и конвертации формата. Подходит для быстрой проверки.

## Цветовая легенда ролей

При визуализации зоны окрашиваются:

| Роль | Цвет | Описание |
|---|---|---|
| `hand` | 🟢 зелёный | Рука текущего игрока (self) |
| `opponent_hand` | 🟡 жёлто-зелёный | Руки оппонентов (left/right/opposite) |
| `wall` | 🟠 оранжевый | Стена (рубашкой вверх) |
| `dead_wall` | 🟣 розовый | Мёртвая стена |
| `dora` | 🟣 magenta | Дора-индикаторы |
| `discard` | 🔵 синий | Сбросы (self/left/right/opposite) |
| `noise` | не рисуется | Кластеры за границами стола |
| `other` | не рисуется | Непривязанные группы |

## Ручная проверка результатов

groups.json — единственный источник истины. Визуализация может врать (цвета
накладываются неточно). Проверять:

1. **hand — 13-14 тайлов** в конце раздачи, может быть меньше на середине
2. **discard — seat определяет, чей сброс** (self внизу, opposite вверху)
3. **dead_wall — 4-14 тайлов**, лицом вверх
4. **dora — 1-5 тайлов**, рядом с dead_wall
5. **не больше четырёх discard и четырёх wall**, места только
   `self/left/opposite/right`
6. **каждый ряд discard — до 6 тайлов**; третий ряд может продолжаться дальше
7. **noise/other — чем меньше, тем лучше**

Структурные ограничения сверены с
[WRC Rules 2022](https://www.worldriichi.org/s/WRC_Rules_2022_20220708_site.pdf):
четыре игрока, свой пул сброса у каждого, мёртвая стена из 14 тайлов и до пяти
индикаторов доры.

Если hand=0 или hand > 18 — эвристика не сработала. Смотреть визуализацию:
возможно, стол детектирован неправильно (жёлтая рамка).

## 5. Метрика группировки

Без неё «стало лучше» проверяется глазами по нескольким картинкам — ровно так
текущие эвристики и оказались подогнаны под пять исходных фото.

Заготовить черновик эталона из текущего выхода:

```bash
PYTHONPATH=vision/src:. python3 vision/scripts/score_layout.py seed \
  ../test/<run>/groups.json ../test/roles-truth
```

По файлу на кадр, все с `"reviewed": false`. Дальше — руками: открыть оверлей из
`../test/<run>/`, сверить роли групп, поправить `role` и `seat`, поставить
`"reviewed": true`. **Непроверенные кадры в метрику не идут** — сравнивать выход
сам с собой бессмысленно, результат всегда был бы идеальным.

```bash
PYTHONPATH=vision/src:. python3 vision/scripts/score_layout.py score \
  ../test/<run>/groups.json ../test/roles-truth
```

В отчёте: precision/recall по каждой роли, `falseRole` — доля тайлов, которым
уверенно назначена неверная роль, `silence` — доля отданных в `other`/`noise`, и
`missedTiles`. Главная цифра — `falseRole`: молчание честно, уверенная ошибка нет.

## Метрика на 2026-07-31

Эталон: `test/roles-truth/`, 8 кадров, 545 размеченных тайлов и 60 помеченных
`unknown`. Роли сверены по оверлеям v10 покадрово; спорное и слипшееся
(например, блок из 22 тайлов на `28de1047`, где стена и сброс попали в одну группу)
помечено `unknown` и из счёта исключено — штрафовать алгоритм за то, чего не
разобрал размечающий, нечестно.

| Прогон | falseRole | silence | hand R | discard R | wall R |
|---|---|---|---|---|---|
| `old-photos-v10` (5 старых) | 0.000 (0/369) | 0.000 | 1.00 (68) | 1.00 (127) | 1.00 (86) |
| `new-photos-v10` (3 новых) | 0.000 (0/176) | 0.000 | 1.00 (40) | 1.00 (116) | 1.00 (13) |
| `new-photos-v9` (без `--faces`) | **0.817** (89/109) | 0.381 | 0.18 | **0.00** | 1.00 |

**Единица в первых двух строках — не доказательство правильности.** Эталон получен
проверкой выхода v10 глазами, поэтому он фиксирует «видимых ошибок при просмотре
нет» и служит защитой от регресса: любое изменение, сдвинувшее роли, вылезет в
таблице. Независимая проверка требует разметки, сделанной без оглядки на выход.

Третья строка — то, ради чего метрика и нужна. Прогон без `--faces` выглядел
правдоподобно (роли расставлены, картинка рисуется), но 89 из 109 уверенных
ответов оказались неверными, а сброс не найден ни разу при 116 тайлах в эталоне.
Глазами такое отличить от «алгоритм чуть хуже работает» нельзя.

## Что показал прогон на новых фото (2026-07-31)

`1785438340-new-test.jpg`, `img_3ac5bb0b89d9.jpg`, `v8-test-3.jpg`,
`v8-test-4.jpg`, `v8-test-5.jpg` — снимки середины партии. Детектор нашёл
71/72/46/97/61 боксов; классификатор лиц — 74/77/63/83/47.

Прогон `new-photos-v24` даёт свою руку 13/14/13/17/17. На каждом кадре не больше
четырёх сбросов; когда правого сброса нет (`v8-test-5`), нижний пул остаётся
`self`, а не сдвигается вправо. На первом кадре синяя стена отделена от верхнего
сброса. Известный промах: крайняя правая рука на `v8-test-4` остаётся `noise`;
агрессивное повышение такого ряда в руку даёт ложную руку на синей стене другого
кадра, поэтому до разметки роли это не включено.

История этого прогона стоит отдельного абзаца, потому что она про метод. Первый
запуск дал 45 из 46 тайлов в `other`, и это выглядело как принципиальная негодность
алгоритма на середине партии — вплоть до плана переписывать эвристики. Причина
оказалась в **одном пропущенном флаге**: номиналы считались без `--faces`, одним
проходом по кадру, и давали 2–4 лица вместо 63–77. Дальше всё разваливалось по
цепочке, потому что четыре правила требуют лиц. Проверка, которая это вскрыла, —
прогон **старых** фото через тот же путь: если бы они тоже сломались, дело было бы в
запуске, а не в алгоритме. Ставить такой контроль до выводов дешевле, чем после.

Что осталось честными ограничениями:

- **Рубашки не детектируются.** Синие стены дают ноль боксов на всех трёх кадрах.
  Открытый пункт ML-05: разметка `back` и дообучение.
- **Полная projective rectification не доказана.** Текущий detection frame
  сохраняет все тайлы и переносит центр вместе с игрой, но не исправляет сильный
  наклон камеры. Перспективу стоит возвращать только с отдельной разметкой углов
  или ключевых точек стола.
- **Разброс детектора влияет на группы.** Пакетный `predict.py` даёт 86/67/86/89/88
  боксов там, где эталонный прогон давал 89/61/88/88/87. На трёх кадрах разница в
  один тайл, на `28de1047` расхождение заметное: 22-тайловый слипшийся `discard`
  вместо `dead_wall` и четырёх сбросов. Группировка чувствительна к ±5% детекций.

Артефакты: `test/new-photos-v24/` (пять новых), `test/old-photos-v10/` (старые тем же
путём), `test/club-baseline-v9/` (эталонные предсказания).
